# DSH Desktop 运维参考

## 支持边界

当前候选只支持 Windows x64。应用使用候选内置 Node.js 启动精确版本 Harness，不读取系统 Node.js、pnpm 或浏览器扩展。产品服务只监听操作系统分配的 `127.0.0.1` 临时端口；窗口只接受同一精确来源。

## 用户状态与工作目录

桌面默认不设置 `DSH_HOME`，因此遵循 Harness 的 `$DSH_HOME`、`~/.dsh` 优先级。卸载、二进制回滚和故障恢复不得删除、迁移或降级该目录。`DSH_DESKTOP_WORKSPACE` 只接受已经存在的 Windows 绝对目录；未设置时使用用户主目录。

## 日志与诊断

“文件 → 打开日志目录”打开 Electron 为当前用户分配的日志目录。日志是单行 JSON 事件，只记录状态、稳定错误码、版本身份和有界诊断；写入前隐藏常见凭据以及 `$DSH_HOME` 的绝对路径和内部相对路径。版本信息视图只展示桌面版本、Harness 版本、Node.js 版本和构建标识。

应用在 `userData/run-state.json` 写入只含启动时间和 PID 的运行标记。正常静止关闭会验证并删除该普通文件；Electron 异常终止会留下标记，下次启动记录 `previous-abnormal-termination`，但不回显环境、工作目录或用户内容。链接、目录或超大无效标记不会被跟随或作为普通文件删除。

## 启动与关闭

启动页保持可见，直到资源清单、全量运行时索引、精确版本、就绪来源和根文档启动清单均通过验证。正常关窗先发送版本化关闭消息并等待 Harness 有界清理；超过截止时间后终止 launcher，使 Job Object 清理完整进程树。强制清理后仍无法确认静止时，应用记录 `shutdown-failed`，刷新日志后以非零状态退出，由 launcher 的父进程消失路径完成最后清理。

第二实例不会启动第二套 Harness；它退出并要求现有主窗口恢复、显示和聚焦。renderer 崩溃会停止当前 Harness 并显示本地故障页，避免在未知页面状态下继续保留运行时。

## 故障恢复

本地故障页显示安全摘要、稳定错误码、“重新启动”和“退出”，并指向日志目录。包完整性、运行时入口、就绪协议、环回探测或工作目录失败都不得回退到系统 Node.js。重新启动会先执行同一静止关闭流程；如果清理失败，旧 Electron 退出后由父进程丢失语义终止 Job。

## 安装与卸载

内部 Squirrel 安装器按用户安装到 `%LOCALAPPDATA%\DshDesktop`。自动化验收在任何安装动作前拒绝覆盖已有目录，并检查内置 Node.js、进程链、回环监听、单实例、正常关闭、快捷方式删除、用户状态保留和卸载残留。当前机器存在旧内部候选留下的 Squirrel 延迟删除残留，因此干净安装与卸载证据必须在新的 Windows 10/11 x64 虚拟机取得。

生产故障处置、签名候选和二进制回滚规则见[发布流程](release.md)，当前证据状态见[验收状态](acceptance.md)。
