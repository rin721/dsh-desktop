## 执行规则

本登记表是拟议桌面工作的任务级事实来源。当前请求仅授权 `DSK-DOC-001`。在用户明确批准已评审计划前，所有实施、依赖、签名、发布和上游贡献任务均保持未确认。

如果目标、进程边界、更新供应路径、监管器契约、受支持操作系统、安装器类型、签名策略或用户数据行为发生实质变化，受影响任务必须恢复到 `pending confirmation`，获得确认后才能继续。

## 状态图例

| 状态 | 含义 |
| --- | --- |
| `pending` | 已定义但尚未开始。 |
| `in progress` | 已授权工作已经开始，但完成证据尚不完整。 |
| `complete` | 完成标准和必需证据均已满足。 |
| `blocked` | 外部决策或依赖阻止了有效推进。 |
| `optional` | 首发版本不需要，且必须单独确认。 |

## 拟议执行顺序

1. 决策轮：完成 DSK-DOC-001，并在不修改应用代码的情况下获得 DSK-DEC-001 确认。
2. 基础轮：完成 DSK-GOV-001、DSK-REP-001、DSK-DEP-001 和 DSK-LCH-001，在构建 UI 细节前先证明可重复的进程包含。
3. 桌面轮：完成 DSK-SUP-001、DSK-WIN-001 和 DSK-SEC-001，然后评审运行时与安全证据。
4. 分发轮：完成 DSK-PKG-001、DSK-TST-001 和 DSK-UPD-001，包括失败候选和回滚演练。
5. 发布轮：完成 DSK-DOC-002 和 DSK-REL-001；在上游贡献获得授权时独立推进 DSK-UP-001。

## 确认检查点

开始任何非文档工作前，用户必须确认主要选择：独立 Electron 伴生仓库、精确官方 npm 依赖、独立固定 Node.js 运行时、环回 HTTP/WebSocket 传输、Windows x64 首发，以及不作为启动前置条件的可选上游监管贡献。
